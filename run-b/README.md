# 五子棋 · 人机对战（Canvas + 原生 ES Modules）

一款**零依赖、零构建**的网页五子棋：原生 JavaScript（ES6+ / ES Modules）写逻辑，Canvas 画棋盘棋子，HTML/CSS 搭界面。支持人机三档难度、双人对战、悔棋重开、棋谱自动保存与逐手复盘。

## 运行方法

因为浏览器对 `file://` 协议下的 ES Module 有 CORS 限制，**直接双击 `index.html` 在部分浏览器会加载不了模块**（页面会给出提示）。请用任意静态服务器打开：

```bash
# 任选一种，在项目根目录执行
python -m http.server 8000          # 然后访问 http://localhost:8000/
npx serve .                          # 然后访问控制台输出的地址
```

VS Code 里安装 Live Server 插件，右键 `index.html` → Open with Live Server 也可以。服务器只是用来提供 http 源，**没有任何构建步骤，也不需要 npm install**。

## 目录结构

按职责拆分成多个模块，`index.html` 只做入口：

```

js/core/board.js           棋盘数据 + 落子规则（合法性校验、悔棋、邻域计数）
js/core/rules.js           胜负判定（横竖斜五连、长连、获胜连线坐标）
js/core/clock.js           对局计时器（整盘用时 / 本手用时 / 暂停恢复）
js/core/game.js            对局状态机（轮次、模式、难度、悔棋、胜负结算）

js/storage/store.js        棋谱持久化（localStorage，只存坐标）
js/ui/renderer.js          Canvas 渲染（棋盘、棋子、落子标记、获胜连线、悬停预览）
js/ui/app.js               界面与交互控制（按钮状态、结算弹窗、计时刷新、存档）
```

## 玩法与功能

- **棋盘**：标准 15 路交叉盘，鼠标点击交叉点落子，黑先白后。刚落下的棋子有红圈标记，鼠标悬停有半透明预览。
- **非法落点**：棋盘外、已有棋子的交叉点都会被拒绝，并用浮动提示说明原因，不会静默失败。
- **胜负**：横、竖、斜任意方向连成 5 子（或更长）立刻判胜，获胜棋子用红色连线 + 金色圆环高亮，并弹出结算画面显示胜方、手数、用时。棋盘下满无五连判平局。
- **模式**：人机对战（玩家执黑先行）/ 双人对战（同盘轮流落子），随时可切换（会重开棋盘）。
- **AI 难度**：
  - `简单`：随机选点为主，只会挡下“对手下一步成五”的明显杀招，一眼能看出在乱下。
  - `普通`：棋型启发式评估 + 浅层搜索（深度 ≤ 4，预算 500ms），会自己做活二、活三并主动进攻。
  - `困难`：迭代加深 + Alpha-Beta 剪枝 minimax + 完整棋型评估（深度 ≤ 8，预算 2000ms），思考期间界面不卡死。
- **悔棋 / 重开**：人机模式下点一次悔棋会**同时回退双方各一手**，回到玩家落子前；对局结束后仍可悔棋继续或重开。
- **按钮状态**：AI 思考期间禁止落子，对局结束后只能悔棋或重开，空盘时悔棋按钮禁用，双人模式下难度按钮禁用。
- **棋谱**：对局进行中每次落子都会把“当前局面”存进 `localStorage`，关掉页面再打开可原样继续（包括轮到 AI 时会自动接着下）；结束后自动归档到“最近棋谱”列表（默认保留最近 12 盘），点击任意一条即可逐手复盘、单步前进/后退或自动播放。
- **后台冻结**：切到别的程序时计时暂停，切回来继续，不会偷跑。

## AI 设计要点

1. **棋型打分（`patterns.js`）**：以落点为中心取前后各 4 格共 9 格，按 `1`（己方）/`0`（空）/`2`（对方或棋盘外）编码成三进制数，直接在 19683 大小的查表数组里取值。成五、活四、冲四（含 `11011` 这类跳四）、活三、眠三、活二、眠二各有不同分值，表只算一次、全程复用。
2. **全盘评估（`evaluator.js`）**：把棋盘切成 15 横 + 15 竖 + 29 + 29 条斜线共 88 条线，每条线一次扫描统计连胜长度与两端开口数，得到活四/冲四/活三/眠三/活二…的分值，再额外识别断点四。叶子节点返回 `我方分 - 对方分 × 1.15`（略偏防守）。
3. **搜索（`engine.js`）**：候选点只取“棋子周围 2 格内的空点”，并用棋型分排序后截断分支（困难档 12 路）。`negamax` 写成 generator，每 256 个节点检查一次时间并 `yield`，驱动器每 4 次 yield 用 `MessageChannel` 把控制权交还事件循环，所以搜索全程界面可响应、按钮可点、动画不停。
4. **硬约束**：能一步成五必成五；对手下一步能成五必堵（含各种冲四/活四杀招）；思考时间留 60ms 安全余量，实测困难档每手 ≤ 2000ms。
5. **搜索隔离**：搜索在 `board.clone()` 出来的副本上进行，界面上真实的棋盘不会被搜索过程中的临时落子污染；悔棋/重开时通过 token 直接作废在跑的搜索。

## 性能与内存

- 棋谱和存档**只保存每手坐标**，不保存整盘快照；`localStorage` 里体积可忽略。
- 棋盘用一维 `Int8Array`，悔棋是 O(1)；另维护一个邻域计数 `Int16Array`，候选点生成只需线性扫一遍，不必对每个点做 5×5 探测。
- 棋型查表是定长 `Int32Array`，不产生字符串垃圾；搜索中临时产生的候选点数组在每手结束后即被回收。
